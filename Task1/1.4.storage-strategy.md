# Стратегия хранения

Стратегия хранения (типы хранилищ)

| Группа данных | Тип хранилища | Обоснование |
| :--- | :--- | :--- |
| **Операционные данные (OLTP)** | **OLTP БД (PostgreSQL / Oracle)** | Счета, договоры, карты, операции, платежи требуют строгой согласованности (ACID), высокого RPS и точечных запросов. Идеально для реляционных систем. |
| **Золотые записи клиентов и справочники** | **MDM (Informatica / Profisee / Reltio)** | Клиенты дублируются между FU CRM и RB CRM. MDM обеспечивает дедупликацию, создание "золотой записи", управление идентификаторами и версионирование справочников. |
| **Регламентированная отчетность и BI** | **DWH (PostgreSQL / Vertica / Oracle)** | Классическое реляционное хранилище с витринами для регуляторной и управленческой отчетности. Требует строгой консистентности и воспроизводимости данных. |
| **Большие исторические и событийные данные** | **Data Lakehouse (ClickHouse + MinIO / S3)** | События карточных операций, логи взаимодействий, истории изменений. Колоночное хранение и сжатие для аналитических запросов. Lakehouse добавляет ACID-гарантии и управление метаданными поверх Data Lake. |
| **Документы, выгрузки, архивы** | **Объектное хранилище (S3 / MinIO)** | Документы клиентов (паспорта, доверенности), выгрузки для регуляторов, архивы старых транзакций. Дешевое масштабируемое хранение. |
| **Связи клиентов и контрагентов** | **Графовая БД (Neo4j / ArangoDB)** | Поиск связей: общие номера телефонов, адреса, платёжные инструменты (антифрод, комплаенс). Обход графа в 2–3 шага для выявления связанных клиентов. |
| **Поиск по обращениям и клиентским данным** | **Поисковый движок (Elasticsearch)** | Быстрый поиск по обращениям, клиентам, транзакциям для колл-центра и операционистов. Поддержка нечеткого поиска и фильтрации. |
