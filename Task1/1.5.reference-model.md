# Референсная модель данных

Референсная модель BIAN

| Сущность | Возможная область BIAN | Зачем это нужно |
| :--- | :--- | :--- |
| **Клиент** | **Party Data Management** | Единый подход к управлению клиентскими данными. Определяет, где хранится мастер-запись клиента, как обрабатываются дубли (MDM), кто владеет данными. Помогает унифицировать FU CRM и RB CRM. |
| **Счет** | **Current Account** / **Account Management** | Унификация модели счёта (текущий/расчётный). Определяет границы между Core Banking и смежными доменами (карты, платежи). Помогает объединить FU Core и RB Core. |
| **Карта** | **Card Management** / **Payment Card** | Стандартизация карточных продуктов, статусов и процессинга. Помогает объединить FU Cards и RB Cards. |
| **Кредитный договор** | **Loan Management** / **Consumer Loan** | Унификация кредитных продуктов, ставок, графиков платежей. Помогает объединить FU Loans и RB Loans и определить, как данные попадают в отчётность. |
| **Депозит** | **Deposit Account** / **Savings Account** | Стандартизация депозитных продуктов, процентных ставок и сроков. |
| **Транзакция** | **Transaction Management** / **Payment Execution** | Унификация форматов транзакций (карточные, безналичные, платежи). Определяет, какие атрибуты обязательны для отчётности и антифрода. |
| **Обращение клиента** | **Customer Interaction** / **Service Engagement** | Стандартизация истории обращений и работы колл-центра. Помогает объединить FU CRM и RB CRM для единого клиентского профиля. |
| **Продукт** | **Product Catalog** / **Product Management** | Унификация справочника продуктов для объединённой компании. Определяет, как связаны продукты с договорами и тарифами. |
| **Справочник** | **Reference Data Management** | Централизованное управление справочниками: отделения, тарифы, коды операций, категории клиентов. Помогает устранить расхождения между системами. |
| **Операция/Платеж** | **Payment Order** / **Payment Initiation** | Унификация платежных поручений и операций для расчётного блока. |
