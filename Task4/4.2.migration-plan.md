# Инкрементальный план миграции

План разбит на шесть этапов, покрывающих 12 месяцев перехода от ландшафта As-Is к целевой
архитектуре из задания 3.

| Этап | Содержание | Результат |
| :--- | :--- | :--- |
| **1. Data Discovery & Governance**<br>(месяц 0–1) | Инвентаризация всех систем, таблиц, потоков данных в FinUnion и RetailBank. Согласование владельцев данных, критичности сущностей, правил качества. Подготовка cross-reference таблиц для клиентов, счетов, продуктов. | Реестр данных (все системы, таблицы, поля). Согласованные Data Owners и Data Stewards. Правила дедупликации клиентов. |
| **2. Интеграционный слой и MDM**<br>(месяц 1–3) | Развёртывание Kafka, Integration Layer. Внедрение MDM Customer Hub и MDM Reference Data. Настройка CDC из FU CRM и RB CRM. Начало дедупликации клиентов. Создание единых справочников (продукты, отделения, коды). | Работающий Integration Layer (Kafka). MDM с золотой записью для 80% клиентов. Единые справочники. |
| **3. DWH и первые витрины**<br>(месяц 3–6) | Развёртывание DWH на PostgreSQL (или Vertica). Настройка ELT-пайплайнов из FU Core и RB Core (через Kafka). Построение первых витрин: «Клиенты», «Счета», «Транзакции». Настройка BI (единые дашборды для руководства). | DWH с данными по FU и RB. Первые BI-дашборды (управленческая отчётность). Регламент сверки данных из двух систем. |
| **4. Data Lakehouse и большие данные**<br>(месяц 6–9) | Развёртывание Data Lakehouse (Iceberg + Trino). Миграция исторических карточных операций и событий каналов. Настройка потоков из Kafka в Iceberg. Построение витрин для антифрода и риск-менеджмента. | Data Lakehouse с историей карточных операций и событий. Витрины для антифрода. Интеграция BI с Lakehouse через Trino. |
| **5. Миграция RetailBank в FU Core**<br>(месяц 9–11) | Поэтапная миграция счетов, кредитов, карт RetailBank в FU Core (по продуктам). Переключение потоков (cutover по продуктам). Перевод RB CRM в режим «только чтение». Полная дедупликация клиентов (100%). | RetailBank работает на FU Core. RB CRM в режиме «только чтение». Все клиенты имеют master_id. Единая регуляторная отчётность. |
| **6. Вывод RB-систем и финализация**<br>(месяц 11–12) | Вывод из эксплуатации RB Core, RB Cards, RB Loans, RB DWH, RB BI (после подтверждения корректности данных). Архивация исторических данных. Внедрение DataHub (каталог и lineage). Настройка мониторинга качества данных. | Только целевой ландшафт. RB-системы выведены. DataHub работает. Мониторинг качества данных. |
