# Технологическая дорожная карта

Технологии разделены на три зоны по готовности к внедрению в объединённом банке.

| Зона | Что включить | Почему |
| :--- | :--- | :--- |
| **Adopt**<br>(внедрить в ближайшие 3–6 месяцев) | **MDM Customer Hub** — дедупликация и золотая запись клиентов. **Kafka** — потоки данных. **Debezium** — CDC. **Airflow** — оркестрация ELT. **DWH (PostgreSQL / Vertica)** — регламентированная отчётность. **DataHub** — каталог данных и lineage. | Это базовые компоненты, без которых невозможно объединение данных. Они решают ключевые проблемы: дубли клиентов, отсутствие единого потока, непрозрачность данных. |
| **Grow**<br>(начать внедрение через 6–9 месяцев) | **Data Lakehouse (Iceberg + Trino)** — исторические и событийные данные. **Data Mesh** (частично) — доменные data-продукты. **Spark** — обработка больших данных. **dbt** — трансформации в DWH. | После стабилизации потоков и DWH можно переходить к масштабированию аналитики. Lakehouse решает проблему больших данных: карточные операции, события. Data Mesh — для автономности доменов. |
| **Experiment**<br>(изучить, но не внедрять в ближайший год) | **Graph DB (Neo4j)** — антифрод и связи клиентов. **ML Platform** — модели скоринга и рекомендаций. **Real-time Streaming (Flink)** — обработка событий в реальном времени. | Эти технологии требуют зрелой платформы данных и компетенций. Graph DB — для антифрода (связи по номерам карт и телефонам), но пока достаточно Lakehouse. ML Platform — для кредитного скоринга и рекомендаций, но требует отдельной стратегии. |
