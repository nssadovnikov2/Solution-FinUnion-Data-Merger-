# Образ целевого результата (Target State)

Ниже описано, как изменится ландшафт данных за 12 месяцев: какие системы остаются, какие выводятся,
какие данные мигрируют и как переключаются потоки.

| Вопрос | Что описать |
| :--- | :--- |
| **Какие системы остаются** | FU CRM (как операционная CRM), FU Core (единое ядро), FU Cards (единый карточный процессинг), FU Loans (единая кредитная система), MDM Customer Hub (золотая запись клиента и справочников), DWH (регламентированная отчётность), Data Lakehouse (исторические и событийные данные), Integration Layer (Kafka + ESB), BI (единые дашборды), DataHub (каталог данных). |
| **Какие системы выводятся из эксплуатации** | RB CRM (выводится после миграции клиентов в FU CRM), RB Core (выводится после миграции счетов), RB Cards (выводится после миграции карт), RB Loans (выводится после миграции кредитов), RB DWH (выводится после консолидации в единый DWH), RB BI (заменяется на единый BI). |
| **Какие данные мигрируются** | Клиенты (маппинг в MDM), счета и остатки, карточные операции (за последние 5 лет), кредитные договоры и графики, обращения клиентов, исторические транзакции (для регуляторной отчётности). Данные мигрируются в DWH (для регламентированной отчётности) и в Lakehouse (для исторических и событийных данных). |
| **Какие потоки переключаются** | Все потоки, идущие из RB CRM → RB Core → RB DWH → RB BI, переключаются на: Integration Layer → MDM (для клиентов) → DWH / Lakehouse (для аналитики) → единый BI. Потоки между FU и RB интегрируются через единую шину (Kafka / ESB), а не через point-to-point. |
| **Критерии подтверждения завершения перехода** | Все клиенты RetailBank имеют master_id в MDM. Все счета и карты RetailBank видны в едином BI. Регуляторная отчётность строится из единого DWH (сводка по FU и RB совпадает). Нет дублей клиентов (дедупликация подтверждена). BI показывает единые дашборды по всем продуктам. RB CRM больше не используется для операций (только архив). Время отклика дашбордов < 5 секунд. DataHub содержит lineage всех критических таблиц. |
