# Аналитическая модель (схема «звезда»)

Для аналитики транзакций выбрана **схема «звезда»**, оптимальная для OLAP-нагрузок — быстрых
агрегаций и срезов.

## 1. Таблица фактов: `fact_transactions`

| Атрибут | Тип | Описание |
| :--- | :--- | :--- |
| `transaction_id` | UUID | Уникальный идентификатор транзакции (первичный ключ) |
| `date_id` | int | Суррогатный ключ на `dim_date` (день) |
| `customer_id` | UUID | Суррогатный ключ на `dim_customer` |
| `account_id` | UUID | Суррогатный ключ на `dim_account` |
| `product_id` | UUID | Суррогатный ключ на `dim_product` |
| `channel_id` | int | Суррогатный ключ на `dim_channel` (канал) |
| `amount` | decimal(18,2) | Сумма транзакции |
| `transaction_type` | text | Тип: пополнение, списание, перевод |
| `transaction_count` | int | Количество транзакций (по умолчанию 1) |

## 2. Таблицы измерений

| Измерение | Атрибуты | Описание |
| :--- | :--- | :--- |
| `dim_customer` | customer_id, master_id, full_name, segment, region, status | Клиентская информация (псевдонимизированная) |
| `dim_account` | account_id, account_number, account_type, currency, open_date, status | Счёт |
| `dim_product` | product_id, product_name, product_type, tariff, terms | Продукт: кредит, карта, депозит |
| `dim_date` | date_id, date, year, quarter, month, day_of_week | Календарная дата |
| `dim_channel` | channel_id, channel_name, channel_type | Канал: мобильное приложение, веб, офис, колл-центр |

## 3. Почему схема «звезда» подходит для OLAP

1. **Простота и скорость запросов.** Нет сложных цепочек JOIN — только факт → измерения. Запрос с
   тремя-четырьмя JOIN выполняется быстро.
2. **Агрегации.** Сумма по дате, клиенту, продукту — тривиальный `GROUP BY`.
3. **Денормализация.** Данные измерений продублированы, что ускоряет чтение — цена этого ускорения
   объём хранения.
4. **Воспроизводимость.** Схема стабильна, витрины пересчитываются детерминированно.
